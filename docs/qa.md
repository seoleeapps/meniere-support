# 검증 기록

2026-10-03 검증. 실제 환자 데이터는 사용하지 않았다. 네이티브 저장 테스트는 `private-qa` 디렉터리와 별도 SecureStore 키만 사용하고 종료 후 제거한다. PDF 시각 확인용 가상 파일만 QA 도구에서 보존한다.

## 자동 검사

- TypeScript 타입 검사 및 플랫폼 독립 코어의 import/네트워크 경계 검사 통과.
- 코어 기존 24개: 미기록/증상 없음 구분, 정확·대략·모름 지속 시간, 기간 경계, 윤년·여행·서머타임, 데이터 검증, 충돌 병합, CSV 이스케이프.
- 문서 생성 기존 4개: HTML 삽입 방지, UI와 동일한 집계, 한영 문구, 다음 페이지의 상세·질문 보존.
- 전정재활 코어 7개 추가: 발작·미확인 운동 시작 방지, 회차 경계·휴식·일시정지, 불가능한 완료 거부, 형식 1 변환, 복원 충돌·기간 요약·CSV, 다른 기기의 운동 계획을 선택해서 교체. 문서 1개 추가: 중단 기록·불편감·계획 이스케이프와 치료 효과 판정 제외. 총 코어 31개·문서 5개.
- 운동 시작 간소화: 선택한 시간·횟수의 저장·복원·확인 해제 및 잘못된 설정 거부 2개 추가. 현재 총 코어 33개·문서 5개와 타입·구조·등록 형식 검사가 통과했다.
- Android APK 빌드와 iOS simulator `.app` 빌드 통과. SDK 버전은 Expo 설치 검사로 확인한다.

## 네이티브 기능

Android Seeker API 36 실기기, 전용 Android API 36 에뮬레이터, iPhone 16 Pro iOS 18.1 시뮬레이터에서 다음 12개 검사를 각각 통과했다.

1. 암호화 DB 저장·읽기
2. 연결을 닫은 뒤 다시 열어도 진행 중 기록 보존
3. 저장 파일에 평문 SQLite 헤더가 없음
4. 비밀번호 백업과 복원 미리보기 왕복
5. 잘못된 비밀번호 거부
6. 실패한 복원 이후 원본 보존
7. 손상된 파일 거부
8. 같은 백업 중복 판별
9. 충돌 시 기존 기록 유지
10. 한국어 네이티브 PDF
11. 영어 네이티브 PDF
12. 네이티브 CSV

재활 기능을 추가한 뒤 Android Seeker 실기기와 iPhone 16 Pro 시뮬레이터에서 재활 기록 암호화 저장·읽기, 재활 비밀번호 백업 왕복, 형식 1 백업 변환·원본 보존 3개를 더해 **15개씩** 통과했다. 제거한 전용 Android 에뮬레이터는 이 확장 검사에 포함하지 않는다.

`METRO_PORT=8091 DEVICE_MATCH=Seeker node scripts/native-qa.mjs`로 실행한다. iOS는 `DEVICE_MATCH='iPhone 16 Pro'`를 사용한다. 개발 앱이 같은 Metro 서버에 연결되어 있어야 한다. 개발용 테스트 진입점은 production JS에서 제거된다.

iOS simulator는 Keychain 검증에 앱 식별자가 포함된 ad-hoc 서명이 필요했다. 서명 없이 빌드한 바이너리의 Keychain 권한 오류를 앱 기능 성공으로 취급하지 않았다. 실제 iPhone 및 스토어 서명 검증은 별도로 남아 있다.

## 화면과 PDF

Android 실기기에서 시작→프로세스 재시작→진행 중 보존→종료 저장→기록 목록 흐름을 확인했다. iOS 시뮬레이터에서 온보딩→시작→종료 저장→목록 이동을 확인했다. 메뉴와 기록 화면은 손가락 스크롤로 이동한다. 한영 네이티브 PDF의 실제 출력 파일을 PNG로 렌더링해 한글·시간·집계·질문 표시를 확인했다. 20개 발작과 긴 질문의 같은 HTML을 Chromium으로 인쇄해 첫 페이지 요약과 전체 상세 보존을 추가 확인했다. 이 긴 문서 검증은 네이티브 출력과 구분한다.

iOS의 기록→생활→도움 이동은 Maestro로 화면 제목과 안내 문구를 확인했다. Android의 standalone QA APK를 기존 설치 위에 업데이트하고 Metro를 종료한 뒤 실행해 기록 보존과 한국어 전환을 확인했다. Google 샘플 배너가 기록 화면에 표시됐다. 이는 실제 광고 ID의 게재나 국가별 동의 검증을 뜻하지 않는다. QA APK는 Android debug 인증서로 서명하며 스토어 배포용 서명이 아니다.

최종 Android manifest에서 자동 백업·기기 이전 제외와 광고 앱 ID를 확인한다. 사용하지 않는 사진·영상 접근, 다른 앱 위에 표시, 생체 인증, 원격 알림 수신과 foreground service 권한은 `blockedPermissions`로 제거한다. 화면 캡처 방지는 `FLAG_SECURE`를 사용한다. Expo ScreenCapture 모듈이 Android 14 이상에서 초기화 시 시스템 관찰자를 등록하므로 일반 권한 `DETECT_SCREEN_CAPTURE`는 유지한다. 이를 제외했을 때 실기기 초기화 오류를 확인했으며, 사진 접근 권한과는 구분한다. 로컬 알림의 권한 요청·실제 전달 검증은 별도 항목이다.

검증 중 발견한 두 결함을 수정하고 네이티브 검사를 재실행했다. SQLCipher 키가 없는 새 연결을 여는 exclusive transaction을 제거하고 단일 저장문의 원자성을 사용했다. SDK 57에서 비동기로 바뀐 파일 복사·이동이 끝난 뒤 복원과 공유를 계속하도록 했다.

## 시각 운동 화면 검증

- Android Seeker 실기기: 고정 휴대폰·시선과 머리 회전의 시범, 손가락 스크롤, 광고 제외, 3초 준비 뒤 전체 화면 X, 15초 한 회차 완료·저장과 15초 세부 기록을 확인했다. 의료진 확인 선택을 `아직이에요`로 되돌렸으며, 15초 기록은 화면 확인용 가상 수행이다. 기존 증상 기록은 보존했다. 최초 최종 APK는 Metro 종료 상태에서 홈 접근성 화면과 전면 실행을 확인했다. 시작 간소화 후 수정 APK의 설치·실행 결과는 아래에 구분한다.
- iOS 시뮬레이터: Maestro로 시범 정지, 15초·2회 선택, 시작·전체 화면 X·광고 없음, 일시정지·재개, 회차 종료·휴식·직접 다음 회차, 30초 완료·저장을 통과했다. 별도 흐름에서 앱을 홈으로 보냈다가 프로세스 종료 없이 복귀해 일시정지·중단·저장을 확인했다.
- iOS 전체 화면 제목이 상태 표시줄과 겹치는 문제를 실제 캡처에서 발견했다. 모달의 자체 SafeAreaProvider로 수정한 뒤 전체 화면 표적과 상태 표시줄의 분리, 도움·중단 버튼이 보이는 화면을 다시 확인했다.
- 재활 세부 기록이 들어간 한영 네이티브 PDF를 다시 PNG로 렌더링해 날짜·운동·30초·2회·불편감·계획 표시를 확인했다.
- 이 검증은 기기의 화면·프로그램·저장을 확인한 가상 수행이다. 사람의 실제 머리 움직임이나 임상 유효성을 평가하지 않았다. 실제 환자 데이터는 사용하지 않았다.

## 운동 시작 간소화와 시범 눈 위치 수정

- 별도 계획 저장과 화면 안의 준비 선택을 제거하고, 빠진 시간·횟수·의료진 확인을 시작 버튼 위에 표시한다. 선택 메모와 운동 전 불편감은 접었다. 시작 직전 현재 발작이 없고 안전한 환경인지 한 번 확인한다. 진행 중 발작 차단은 유지한다.
- iPhone 16 Pro 시뮬레이터에서 Maestro로 별도 계획 저장·메모 없이 15초 한 회차 시작·완료·저장, 준비 확인 취소 후 미시작, 같은 운동 재방문 후 다시 시작 가능한 상태, 의료진 확인 해제·재방문 후 해제 유지, 상하 시범 재생·정지를 확인했다. 재방문 화면의 15초·1회 선택은 접근성 `radio button, checked`와 실제 캡처를 함께 읽어 확인했다. 확인은 가상 QA 선택이며 종료 전에 해제했다. 테스트 도구의 돌아가기 버튼 중앙 정렬·홈 이동·선택 항목의 접근성 이름에 맞춰 탐색과 선택자를 보완했다.
- 좌우·상하 시범의 재생 중·정지 화면을 실제 캡처해 눈이 얼굴 앞쪽에서 머리와 함께 움직이는 것을 확인했다. 시선 점선도 눈의 회전 좌표에서 고정 X로 이어진다. Android 단독 실행 APK의 캡처 방지는 유지하며, 이 시각 캡처는 iOS 시뮬레이터 증거다.
- Android Seeker에 수정 단독 실행 QA APK를 기존 자료를 보존하는 업데이트로 설치했다. 기기의 설치 시각 20:34:44, 시작 `ok`와 홈 화면 렌더링, 새 운동 화면의 시작 조건 안내·기존 계획 저장 버튼 제거를 접근성 화면으로 확인했다. Android에서는 의료진 확인을 대신 체크하거나 실제 운동을 시작하지 않았다. Google Play Protect 검사 창 이후 설치 성공을 확인했으며 검사를 비활성화하지 않았다.
- 수정 APK는 `artifacts/Meniere-Journal-0.1.0-rehab-fix-qa.apk`, SHA-256 `3a6a5b359f03b7a90b2e168e50c05e92cc524f9d2d2de4d4609b722d52342f19`다. debug 인증서·Google 샘플 광고를 사용하며 스토어 업로드는 하지 않았다.
