# Data safety 검토와 Console 저장

2026-10-04 Android 소스와 [Google Mobile Ads 데이터 공개 자료](https://developers.google.com/admob/android/privacy/play-data-disclosure)를 다시 대조하고 Console의 최종 저장을 완료했다. 실제 AAB의 Google Mobile Ads 25.4.0과 UMP 4.0.0을 대상으로 한다. 저장은 심사 제출·승인이 아니다. 최종 동의 설정과 production 후보 기기 동작은 아직 검증하지 않았다.

| 증상·생활·전정재활 기록, 진료 질문과 메모 | SQLCipher로 기기에만 저장. 광고·분석·서버 요청에 넣지 않음 | 앱 개발자의 수집·공유 없음. 기기 내 처리와 사용자 직접 선택하는 내보내기를 구분             |

광고 SDK 목적은 광고, SDK 분석 및 부정 사용 방지다. 전송 데이터는 Google 문서의 TLS 보호를 확인했다. 자체 원격 제품 분석은 없다. SDK에 알려진 자동 수집을 앱의 비개인화 요청만으로 `없음`으로 신고하지 않는다.

`App.tsx`의 배너 요청은 `requestNonPersonalizedAdsOnly: true`이며 키워드·증상·메모·의료 관심사나 위치를 전달하지 않는다. `adapters/ads.ts`는 UMP의 `canRequestAds` 확인 이후 광고를 초기화한다. 동의 오류와 광고 불가 상태에도 기록 기능은 사용할 수 있다. 광고 동의 설정과 실제 거절 동작은 production 후보로 검증해야 한다.

외부 계정 생성은 없고 계정 삭제 웹 양식은 필요하지 않다. 사용자는 앱의 전체 또는 개별 기기 기록 삭제를 사용할 수 있다. Google SDK가 보유하는 정보를 기기 기록 삭제가 함께 삭제한다고 안내하지 않는다.

## 실제 저장한 답변

`legacy-admob` / Seolee Apps / 개발자 ID `5547060480954653351` / 앱 ID `4975784705764720395`의 데이터 보안 설문에서 네 유형을 저장했다. [Console CSV](data-safety.csv)를 내려받아 선택한 유형과 각 응답을 대조했다. 저장소 파일은 줄바꿈과 CSV 인용 형식만 정규화했으며 모든 필드가 원본 다운로드와 일치함을 확인했다. Console의 `변경사항이 저장되었습니다. 게시 개요에서 전송하여 검토를 받으세요.`와 대시보드의 데이터 보안 완료 표시를 확인했다.

- 대략적인 위치, 앱 상호작용, 진단, 기기 또는 기타 ID를 각각 수집·공유로 신고했다.
- 네 유형 모두 임시 처리가 아니며 수집 필수, 수집·공유 목적은 애널리틱스, 광고 또는 마케팅, 사기 예방·보안·규정 준수다.
- 정밀 위치, 별도의 기타 앱 성능 데이터, 건강·운동 기록, 개인 메모·파일은 선택하지 않았다. 실제 SDK 공개 자료의 성능 정보는 진단으로 신고했다.
- 전송 중 암호화 있음, 계정 생성 없음, 앱 외부에서 만든 계정으로 로그인 없음을 신고했다.
- 광고 SDK가 보유하는 정보까지 삭제하는 요청 수단은 없다고 신고했다. 앱의 기기 기록 삭제는 그대로 제공하며 이 둘을 동일하게 안내하지 않는다.

광고 ID를 Android 설정에서 제어할 수 있어도 SDK의 app set ID까지 모두 선택 수집이라는 뜻은 아니므로 기기 ID 전체를 선택 수집으로 신고하지 않았다. 원격 제품 분석 미사용은 광고 SDK의 애널리틱스 목적이 없다는 뜻도 아니다. 광고 동의와 실제 거절 시 기록 기능 동작은 별도의 기기 검증 조건이다.
